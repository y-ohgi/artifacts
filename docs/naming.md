# サービス名の候補

このリポジトリ(単体HTMLをアップロードして非公開で保管し、必要なものだけ公開してURLを渡すサイト)の名前を決めるための検討メモ。決定ではなく候補と評価軸の記録。

## 参照した先行事例

BASE社の社内HTMLホスティング「pon」([BASEプロダクトチームブログ](https://devblog.thebase.in/entry/pon))。名前の由来は「ファイルをポンと置きたい」で、社内で「資料をponしました」と**動詞として使われた**ことで一気に浸透した、と記事にある。命名の狙いとしてこの事例を基準に置く。

## 評価軸

pon が機能した理由を分解すると、名前に求めるものは次の6点になる。

1. **動詞化できる** — 「ponしました」のように会話へそのまま入る。これが最重要。名詞のままだと「〜にアップロードしました」と説明的になり、浸透しない
2. **2〜3音で言える** — 口頭で摩擦がない
3. **聞いて書ける** — 表記ゆれ(伸ばし棒、促音、綴り)が起きない
4. **サブドメインとコマンド名として自然** — `xxx.example.com` と `xxx index.html` の両方で成立する
5. **既存の強い意味と衝突しない** — 検索したときに別のものが出てこない
6. **中身の変化に耐える** — 将来機能が増えても意味が破綻しない(例: `html-host` のような機能名は破綻する)

## 観点1: 擬音(pon 直系) — 「動作の軽さ」を名前にする

pon と同じ発想。日本語話者なら説明ゼロで動作が伝わる。

| 候補 | 由来 | コメント |
| --- | --- | --- |
| **peta** / ぺた | ぺたっと貼る | 擬音と「貼る」動作が同時に入る唯一の候補。「ペタしました」が自然。SI接頭辞のペタ(10^15)とも掛かり、uidの空間 36^10 ≈ 3.7×10^15 = 約3.7ペタ通りという偶然もある。懸念は動物愛護団体 PETA |
| **poto** / ぽと | ぽとっと落とす | pon にいちばん近い響き。空いている(`pota` はOSSに2件あるが `poto` は薄い) |
| **hoi** / ほい | 「ほい、これ」と渡す | 保管より**受け渡し**の擬音。共有が主目的ならこちら。3文字で最短級 |
| **choi** / ちょい | ちょい見せ | 「ちょい見せる」= 公開機能と直結。軽さが出る |
| **pochi** / ぽち | ポチッと押す | 可愛いが、押す動作=クリックであって置く動作ではない。犬の名前の印象も強い |
| **patto** / ぱっと | ぱっと出す | 促音の綴りが揺れる(patto/pat/paltto)ので軸3で落ちる |
| **poi** / ぽい | ぽいっと投げる | 「ぽい捨て」の連想で、保管するものに付ける名前としては逆方向 |

## 観点2: 日本語の動詞そのまま — 「何をするツールか」を名前にする

擬音より意味が直接的。動詞化が自明(軸1に最も強い)。

| 候補 | 由来 | コメント |
| --- | --- | --- |
| **haru** / はる | 貼る | 「haruに貼った」「haruしといた」。pastebin的な動作にそのまま重なる。響きが柔らかい。人名・季節語なので検索性は弱い |
| **oku** / おく | 置く・送る | 3文字。「置く」と「送る」の二重の意味を持つのが強い(保管と共有の両方) |
| **dasu** / だす | 出す | 公開操作そのもの。ただし保管が既定のこのサービスとは重心がずれる |
| **miseru / mise** / みせ | 見せる・見世 | 「miseに出す」。動詞と場所の両義。フランス語 *mise* と衝突 |
| **kakeru** / かける | 掛ける(掛軸を掛ける) | 4音でやや長い。「掛ける」は多義すぎる |

## 観点3: 場所・器の比喩 — 「どこに置くか」を名前にする

一覧画面が主役になる見方。名詞なので動詞化は弱いが、「棚に置く」のように前置詞的に使える。

| 候補 | 由来 | コメント |
| --- | --- | --- |
| **tana** / たな | 棚 | 「棚に置く」「棚から出す」が自然。短く、置き場そのもの。素直で強い |
| **okiba** / おきば | 置き場 | 意味は100%伝わる。3音でやや長く、味は薄い |
| **kura** / くら | 蔵 | 保管の重み。「蔵出し」で公開も表現できる。回転寿司の印象 |
| **kabe** / かべ | 壁 | 貼る場所。観点2の *haru* と対になる |
| **engawa** / えんがわ | 縁側 | 内と外の中間領域という比喩が、既定非公開+選択的公開の構造に驚くほど合う。ただし4音で長く、外国人には説明が必要 |
| **nook** | 隅・こもれる場所 | 英語圏でも柔らかい印象。動詞化できない |

## 観点4: 公開/非公開の切り替えを名前にする — このサービスの本質

このサービスの設計上の中心は「既定は非公開、明示的に公開へ、いつでも戻せる」(FR-022〜FR-032)。そこを名前にする案。

| 候補 | 由来 | コメント |
| --- | --- | --- |
| **noren** / のれん | 暖簾 | 「のれんを出す」= 公開、「のれんを下げる」= 非公開。トグルの比喩として完璧で、UIの語彙まで決まる。Node向けOSS `noren` が存在(小規模) |
| **shoji** / しょうじ | 障子 | 光は通すが中は見えない。美しいが動作に結びつかない |
| **mado** / まど | 窓 | 開ける/閉める。ありふれている(Windows連想) |
| **omote** / おもて | 表 | 「表に出す」= 公開。裏/表の対が公開状態そのもの |
| **ajar** | 半開き(英語) | 概念としては秀逸だが、日本語話者には一瞬で伝わらない |

## 観点5: 英語短語 — 将来の外部公開・OSS化を見据える

複数名利用(US6)を越えて外部へ出す可能性を重く見るならこちら。

| 候補 | 由来 | コメント |
| --- | --- | --- |
| **plop** | ぽとんと置く音(英語) | pon の英語版。英語圏でも「plop it there」で動詞化する。日英どちらでも動作が伝わる稀な候補 |
| **tack** | 画鋲で留める | 「tack it up」。貼る動作+短い。ネットワーク用語 ACK と近い |
| **stash** | しまい込む | git stash と衝突。既定非公開の含意は正確 |
| **shelf** | 棚 | 観点3の *tana* の英語版。動詞化できる(shelve) |
| **peek** | 覗く | 閲覧側からの名前。共有される側の体験を名前にする発想 |

## 観点6: 技術的メタファー — 対象物の正確さを名前にする

「単体で完結した1つのHTML」という対象の性質を名前にする。開発者向けには誤解が少ないが、味は出にくい。

| 候補 | コメント |
| --- | --- |
| **solo** | 単体HTML(外部参照なし)という前提そのもの。一般語で埋もれる |
| **onefile / 1f** | 正確だが説明的で、軸1(動詞化)と軸6(拡張耐性)に弱い |
| **doctype** | 開発者にはHTMLだと即座に伝わる。長く、動詞化できない |
| **blob** | R2に置くバイト列。内部実装の語彙であってユーザーの語彙ではない |

## 絞り込み

| --- | --- | --- | --- | --- | --- | --- |
| **peta** | ◎ | ◎ | ◎ | ◎ | △(PETA) | ◎ |

### 推薦: peta(ぺた)

- **由来**: HTMLをぺたっと貼ると、URLが返ってくる
- **会話**: 「さっきの構成図、petaに貼っときました」「petaってあります?」「ペタしました」
- **URL**: `peta.<domain>/<uid>/<name>.html`
- **CLI(将来)**: `peta index.html` → URLを標準出力
- **なぜ**: 「ぺた」は擬音でありながら「貼る」という動作を含む。pon が「置く」だけを表すのに対し、こちらは*何をどうするか*まで1語で入る。ペタ(10^15)と読めるためテック文脈でも浮かず、favicon も絵文字1つで済む
- **懸念**: 英語圏では動物愛護団体 PETA が先に想起される。個人・社内利用なら実害はないが、外部サービスとして出すなら避ける

### 次点1: haru(はる)

動詞そのままで浸透の速さは最強。「haruに貼った」が説明不要。柔らかく長く使える。検索性の弱さ(人名・季節語)は自分用サイトならむしろ無害。

### 次点2: noren(のれん)

「のれんを出す/下げる」が公開トグルの語彙になり、UIの文言まで一貫させられる点が他の案にない価値。名前がプロダクトの設計思想(既定は非公開)を説明してくれる。動詞化の弱さと5音の長さが弱点。

## 決め方の提案

紙の上で選ぶと外すので、次の3つを実際に書いてみて違和感の少ないものを採る。

1. Slackで人に渡す文: 「〇〇に置いたので見てください → https://…」
2. 自分への説明: 「〇〇って何?」に一文で答える
3. コミットメッセージ: 「〇〇へアップロードする導線を追加」

そのうえで、サブドメイン、GitHubリポジトリ名、(将来CLIを出すなら)npm名の空きを確認する。
