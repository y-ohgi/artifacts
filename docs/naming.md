# サービス名の候補

このリポジトリ(単体HTMLをアップロードして非公開で保管し、必要なものだけ公開してURLを渡すサイト)の名前を決めるための検討メモ。決定ではなく候補と評価軸の記録。

## 参照した先行事例

BASE社の社内HTMLホスティング「pon」([BASEプロダクトチームブログ](https://devblog.thebase.in/entry/pon))。名前の由来は「ファイルをポンと置きたい」で、社内で「資料をponしました」と**動詞として使われた**ことで一気に浸透した、と記事にある。命名の狙いとしてこの事例を基準に置く。

## 評価軸

pon が機能した理由を分解すると、名前に求めるものは次の6点になる。

1. **動詞化できる** — 「ponしました」のように会話へそのまま入る。これが最重要。名詞のままだと「〜にアップロードしました」と説明的になり、浸透しない
2. **2〜3音で言える** — 口頭で摩擦がない
3. **聞いて書ける** — 表記ゆれ(伸ばし棒、促音、綴り)が起きない
4. **サブドメインとコマンド名として自然** — `xxx.example.com` と `xxx index.html` の両方で成立する
5. **既存の強い意味と衝突しない** — 検索したときに別のものが出てこない
6. **中身の変化に耐える** — 将来機能が増えても意味が破綻しない(例: `html-host` のような機能名は破綻する)

## 観点1: 擬音(pon 直系) — 「動作の軽さ」を名前にする

pon と同じ発想。日本語話者なら説明ゼロで動作が伝わる。

| 候補 | 由来 | コメント |
| --- | --- | --- |
| **peta** / ぺた | ぺたっと貼る | 擬音と「貼る」動作が同時に入る唯一の候補。「ペタしました」が自然。SI接頭辞のペタ(10^15)とも掛かり、uidの空間 36^10 ≈ 3.7×10^15 = 約3.7ペタ通りという偶然もある。懸念は動物愛護団体 PETA |
| **poto** / ぽと | ぽとっと落とす | pon にいちばん近い響き。空いている(`pota` はOSSに2件あるが `poto` は薄い) |
| **hoi** / ほい | 「ほい、これ」と渡す | 保管より**受け渡し**の擬音。共有が主目的ならこちら。3文字で最短級 |
| **choi** / ちょい | ちょい見せ | 「ちょい見せる」= 公開機能と直結。軽さが出る |
| **pochi** / ぽち | ポチッと押す | 可愛いが、押す動作=クリックであって置く動作ではない。犬の名前の印象も強い |
| **patto** / ぱっと | ぱっと出す | 促音の綴りが揺れる(patto/pat/paltto)ので軸3で落ちる |
| **poi** / ぽい | ぽいっと投げる | 「ぽい捨て」の連想で、保管するものに付ける名前としては逆方向 |

「単体で完結した1つのHTML」という対象の性質を名前にする。開発者向けには誤解が少ないが、味は出にくい。

| 候補 | コメント |

### 推薦: peta(ぺた)

- **由来**: HTMLをぺたっと貼ると、URLが返ってくる
- **会話**: 「さっきの構成図、petaに貼っときました」「petaってあります?」「ペタしました」
- **URL**: `peta.<domain>/<uid>/<name>.html`
- **CLI(将来)**: `peta index.html` → URLを標準出力

理由の詳細は「[peta を掘り下げる](#peta-を掘り下げる)」に分けた。

### 次点1: haru(はる)

動詞そのままで浸透の速さは最強。「haruに貼った」が説明不要。柔らかく長く使える。検索性の弱さ(人名・季節語)は自分用サイトならむしろ無害。

### 次点2: noren(のれん)

「のれんを出す/下げる」が公開トグルの語彙になり、UIの文言まで一貫させられる点が他の案にない価値。名前がプロダクトの設計思想(既定は非公開)を説明してくれる。動詞化の弱さと5音の長さが弱点。

## peta を掘り下げる

一言でいうと **「peta は、単体HTMLをぺたっと貼って、URLを渡すための置き場」**。

- 日本語タグライン: 「ぺたっと貼って、URLを渡す。」
- 英語タグライン: "Paste an HTML. Get a link."

以下、なぜこの4文字がこのサービスに合うのかを分解する。

### 1. 三層の意味が同じ4文字に重なっている

| 層 | 読み | 効果 |
| --- | --- | --- |
| 擬音 | ぺた(っと) | 軽い。準備がいらない。一瞬で終わる |
| 動作 | 貼る | 何をするツールかが分かる |
| 単位 | ペタ(10^15) | テック文脈で浮かない。規模の含意 |

pon は擬音の層だけを持つ。peta は**擬音でありながら動作を指している**点が違う。「ぽん」だけでは何をしたのか(置いた? 押した? 投げた?)が曖昧だが、「ぺた」なら貼ったことが確定する。名前の情報量が1層多い。

### 2. 「貼る」がこのサービスの実態と正確に一致する

このサービスがやることは、受け取ったバイト列をそのまま置き、URLで指し示すこと(FR-011・FR-012)。やらないことは、ビルド・変換・実行環境の提供・ナビゲーションの注入。

「デプロイ」「ホスティング」「公開」を名前にすると期待値が過大になる(ビルドしてくれるのか? 独自ドメインは? APIは?)。「貼る」は**紙1枚をそのまま貼るだけ**という含意なので、単体HTML前提(spec の Assumptions)まで名前が正しく伝える。

機能ではなく**制約**を名前で伝えられるのは珍しい利点で、後から「これは peta の仕事ではない」と言える基準になる。

### 3. 既定が非公開である設計と矛盾しない

「貼る」は貼る場所によって公開範囲が変わる語である(手帳に貼る / 掲示板に貼る)。だから「まず自分の手元に貼る → 必要なものだけ表に出す」という2段階が名前と自然に共存する。

`publish` / `share` / `post` 系の名前だと、既定は非公開(FR-022)という中心的な設計と名前が正面から矛盾する。ここは意外と効く差で、UIの語彙もそのまま決まる。

- 「ペタする」= アップロード
- 「貼った日時」= `uploaded_at`
- 「表に出す / のれんを下げる」= 公開状態の切り替え
- 「貼り替え」= 将来の差し替え機能

### 4. 音と打鍵に摩擦がない

- **CVCV(2拍)** — 日本語の擬音の標準形(ポチ、パタ、ピタ、ペコ)。口が勝手に動く語形
- **無声破裂音で始まり無声破裂音で切れる**(/p/…/t/) — 粘りがなく、動作が一瞬で終わる印象と音が一致する
- **表記が一意** — 「ぺた」のローマ字は `peta` 以外に書けない。伸ばし棒・促音・拗音を含まないので表記ゆれが起きない(pon と同じ性質)。`patto` や `pyoi` はここで落ちる
- **4打鍵、シフトも記号もハイフンもなし** — `peta.<domain>`、`peta index.html`、Slackの `/peta`、MCPツール名 `peta_upload` がすべて自然に収まる
- **英語話者もほぼ迷わず読める** — petal / pedal からの類推で /ˈpetə/。擬音の意味は伝わらないが、読めない・打てないという事故は起きない

### 5. 動詞化の受け皿が広い

pon の浸透理由は「資料をponしました」と動詞化されたことだった。peta はサ変動詞化と名詞化の両方に乗るため、言い方が1つに限られない。

> 「ペタしました」「ペタっとくね」「もうペタった」「ペタ済み」「ペタ先のURL」「これ要ペタだね」

会話に登場する形が多いほど、名前は速く定着する。

### 6. ペタ(10^15)というダブルミーニングの実利

- 単位なので「膨大」の含意がある。1人用 → 複数ユーザー → 生成物が積み上がる、というこのサービスの成長の物語に乗る
- 数字がそのまま説明に使える。uidは `a-z0-9` の10文字なので空間は 36^10 ≈ 3.66×10^15、**約3.7ペタ通り**。名前と設計値が呼応する
- ビジュアルの方向も決まる。付箋・テープ・ラベル。「少しずれて貼られた紙」をモチーフにできる

### 7. 拡張耐性 — 名前がスコープの門番になる

| 将来の変化 | peta は壊れるか |
| --- | --- |
| CLI を出す(`peta index.html`) | 壊れない |
| Slack連携・MCPサーバ | 壊れない |
| 画像やPDFも貼れるようにする | 壊れない(貼る対象は「見せるもの」) |
| 複数ファイル・zip を受ける | やや薄れる(「1枚もの」の含意が緩む)が致命的ではない |
| 実行環境を提供する(SSR、APIサーバ) | **壊れる**。「貼る」の枠外 |

最後の行が重要で、ここへ踏み込むなら別サービスとして名前を分けるべき、という判断基準を名前自体が与えてくれる。名前が広すぎると(例: `platform`、`host`)この歯止めが効かない。

### 8. 他候補に対して優れている点

| 候補 | peta と比べて足りないもの |
| --- | --- |
| pon | 「置く」だけで、何をしたかが確定しない。加えて先行事例(BASE)と衝突する |
| haru | 動詞は強いが擬音の軽さがなく、検索性が最も弱い(人名・季節語) |
| tana | 場所であって動作がない。動詞化できない |
| noren | 公開の比喩に寄りすぎ、保管が既定という重心を表せない |
| plop | 英語話者には効くが、日本語の口に乗らない |

### 9. リスクと運用方針

| リスク | 対処 |
| --- | --- |
| 動物愛護団体 PETA との混同 | **常に小文字 `peta`**。ロゴも小文字、全大文字表記を使わない。英語圏へ本格的に出すなら修飾付きドメイン(`peta.page`、`petapeta`)を検討 |
| SI接頭辞由来の一般語 | 商標としての識別力が弱く、文字商標単独での登録は難しい前提で考える。ロゴや図形との組み合わせ、修飾語の追加を検討 |
| 「ペタバイト」で大容量ストレージと誤解される | タグラインで補正する(「ぺたっと貼って、URLを渡す。」) |
| 擬音が非日本語話者に伝わらない | **名前を説明しない**。説明が必要な名前は説明せず、英語タグラインで動作だけを伝える("Paste an HTML. Get a link.") |

## ドメインの空き状況(2026-07-28 調査)

調査方法: IANAのRDAPブートストラップ(`https://data.iana.org/rdap/dns.json`)でTLDごとのRDAPサーバを解決し、`peta.<tld>` を問い合わせた(107 TLD)。RDAP非対応のTLDはDoH(`dns.google/resolve`)でNS委任の有無を見た。各ゾーンについて `nic.<tld>` などの既知の登録が `delegated` として観測できることを対照確認済み(`nic.nz` のみ対照なし)。

### 主要TLDは全滅

### 空き(レジストリのRDAPが "Object not found" を返した。高信頼)

- **短いccTLD**: `gd` `fm` `ly` `re` `sg` `cx` `pw`
- **新gTLD**: `run` `click` `pro` `tools` `cloud` `space` `live` `studio` `store` `shop` `software` `systems` `team` `works` `world` `zone` `wiki` `media` `network` `land` `life` `house` `group` `company` `codes` `digital` `blog` `blue` `green` `pink` `red` `plus` `press` `pub` `rocks` `ninja` `ink` `fyi` `agency` `wtf`

### 空きの可能性(RDAP非対応。DNS委任が無く、対照確認は通っている。中信頼)

`sh` `st` `so` `ac` `gg` `im` `mn` `my` `nu` `pe` `sx` `vc` `nz` — レジストラのwhoisで最終確認が必要。

Cloudflareのダッシュボードで実際に検索したところ、上の表とは違う結果が出た。

- **`peta.cloud`** — 「プレミアム」表示で **$200.20/年**(ベース価格$21.11の約10倍)
- **`peta.fyi`** — 「すでに登録されているため使用できません」

**RDAPとDNSでは「登録済みかどうか」しか分からず、「レジストリ予約」と「プレミアム指定」を検知できない。** `peta.fyi` については、`nic.fyi` を対照に使ってRDAPサーバが正しく登録を返せることを確認したうえで、`peta.fyi` 自体はレジストリに登録が無いと出る。それでも買えないのだから、これは登録済みではなく**予約またはプレミアムブロック**である。

原因は名前の性質にある。`peta` は4文字・辞書語・SI接頭辞・著名団体名を兼ねるため、多くのレジストリがプレミアムまたは予約に指定している。**したがって上の価格表はベース価格の一覧であり、`peta.<tld>` の実際の取得価格を表していない。** ベース価格が安いTLDほどプレミアム指定の対象になりやすい傾向すらある。

無認証で参照できるソース(RDAP、DoH、Porkbunの公開価格API、Gandiのcheck API)では、いずれも名前単位のプレミアム価格を取得できなかった。**`peta.<tld>` を狙う場合、Cloudflareのダッシュボードで1件ずつ検索するしかない。**

### 他社で買ってCloudflareへ移管する場合の制約

[Cloudflareの移管ドキュメント](https://developers.cloudflare.com/registrar/get-started/transfer-domain-to-cloudflare/)に明記されている前提条件のうち、購入計画に影響するもの:

- **登録から60日経過していないと移管できない**(ICANNの規定)。直近60日に移管したものも不可
- **登録者名・組織・メールアドレスを直近60日以内に変更していないこと**(同じくICANN)
- Cloudflareアカウントに有効な支払い方法があり、登録者メールが検証済みであること
- 移管すると登録期間が1年延長される(その分の支払いが発生する)

つまり**他社で買う場合は最低60日はそのレジストラで運用することになる**。その間のDNSはCloudflareに向けられる(ネームサーバ変更はレジストラを問わず可能)ので、Workersの運用開始を待つ必要はない。移管はあくまで請求先と管理画面の集約が目的になる。

### レジストラの選択(2026-07-30 調査)

**プレミアムと予約はレジストリの決定であり、レジストラを変えても解決しない。** Cloudflare Registrarは標準ドメインもプレミアムも[レジストリ原価で販売しマークアップを載せない](https://www.cloudflare.com/application-services/solutions/low-cost-domain-names/)。したがって `peta.cloud` の$200.20はレジストリの卸価格そのもので、**他社へ移ると同額か高くなる**(Porkbunはプレミアムに低率のマークアップ、Namecheapは運用費分のマークアップを載せる)。`peta.fyi` は予約なのでどのレジストラでも買えない。

**他社を検討する意味は、価格ではなくTLDのカバレッジにある。** Cloudflareの対応は375 TLDでccTLDが薄く、前回上位に挙げた `peta.sh` `peta.click` `peta.gd` `peta.st` はいずれもCloudflareでは扱っていない。

**購入先はWorkers運用を縛らない。** どのレジストラで買ってもNSをCloudflareへ向けられるため、レジストラとDNSは分離できる。ccTLDが必要なときだけ他社を使い、DNSはCloudflareに集約するのが素直。

この件での結論:

- **`petapeta.dev` を採るならCloudflareのままが最安**(更新$12.87相当を原価で、マークアップ0)。他社へ行く理由がない
- **`peta.click`(更新$10.81)を狙うならPorkbunかDynadot**。「ぺた」の擬音とクリック感が近く、Cloudflare非対応TLDの中では価格・意味ともに最も現実的
- `peta.sh` は更新$46.65。4文字なのでプレミアム指定の可能性が残り、実額はカート投入時に確認する

**避けるべきもの**(Cloudflare非対応だが記録として残す):

- **`.ly`** — リビア管轄で、過去にコンテンツを理由としたドメイン停止の事例がある(2010年の `vb.ly`)。**ユーザー由来のHTMLを配るサービスでは管轄リスクが直接効く**
- **`.pw`** — 空きだがスパム送信元としての評判が悪く、メールゲートウェイやフィルタで弾かれやすい。公開した生成物が届かない事故につながる

### 注意点

- **RDAPで未登録でも必ず買えるとは限らない**。レジストリ予約語、プレミアム価格(4文字の一般語は対象になりやすい)、現地要件(`.eu` はEU居住要件)がある。実際の価格はレジストラで確認する
- **初年度価格で選ばない**。`.space` は初年度$1.96だが更新$26.26で、13倍になる。長期保有する前提なので更新価格で比較する
- 価格の出典は Porkbun の公開価格API(卸価格の代理指標)。**Cloudflareの実額はダッシュボードのドメイン検索で確認する**
- **Issue #23 のP0-1(生成物を別ホストへ分離)を採るなら、ドメインは2つ必要になる**。管理画面用と生成物配信用を分ける目的はドメイン評判の巻き込みを避けることなので、生成物側は評判が壊れても切り離せる安価なTLD、管理画面側は堅いTLDという組み合わせが合理的(例: 管理 `peta.run` + 生成物 `peta.click`)
